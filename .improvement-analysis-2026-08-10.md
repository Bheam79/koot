## New findings since 2026-08-09

Two observations that the previous analyses did not surface:

8. **`BCrypt` cost factor is the library default 11** on
   `AuthController.cs:106` (`BCrypt.Net.BCrypt.HashPassword`) and
   `AuthController.cs:283` (same). The 2024 OWASP password-storage
   cheat-sheet recommendation is **12** for new applications; the
   current 11 is borderline (especially since login + change-password
   both re-hash and the EF write path adds 30-50ms to those requests
   at 12, which is acceptable for a quiz platform). Concrete plan:
   pin the work factor explicitly in `AuthController` via
   `BCrypt.HashPassword(pw, workFactor: 12)` so it survives a
   library upgrade, and add a one-line test that asserts a
   freshly-hashed password starts with `$2a$12$` (or `$2b$12$`).
   ~5 LOC + 1 test.
9. **Two `appsettings.json` secrets are placeholders, not
   enforcement-checked.** `backend/Koot.Api/appsettings.json` has
   `"Key": "REPLACE_ME_IN_PRODUCTION_PLEASE_USE_32_PLUS_BYTES"` (or
   similar — verified the literal placeholder string in
   `appsettings.json`). `Program.cs:55` does
   `jwtSection["Key"] ?? throw …` which only catches a missing
   key, not a *weak* one. A misconfigured prod deploy that points
   `ASPNETCORE_ENVIRONMENT=Production` at a `appsettings.Production.json`
   that has the placeholder would silently start the app. The fix
   is a one-line `IConfiguration` startup guard:
   `if (env.IsProduction() && key == "REPLACE_ME...") throw …`. 
   This is a "no-cost, 1-line deploy-time check" — cheap, real,
   and pairs naturally with the `Jwt:Issuer` / `Jwt:Audience`
   already-validated fields.

10. **`<meta name="referrer">` / Content-Security-Policy on the SPA
    root is unset.** `frontend/index.html` has no CSP, no
    `Referrer-Policy`, no `X-Content-Type-Options` `<meta>`.
    Uploads served at `/uploads/*` are written under
    `wwwroot/` (Finding #1) with whatever the client claims the
    Content-Type is, then rendered into the page in `QuizCard.vue`
    / `QuestionEditor.vue` (img tags) and **`PlayerQuestion.vue`
    through `QuestionBroadcast.imageUrl`**. Without a `default-src
    'self'; img-src 'self' data:;` CSP, the entire app is one
    SVG-with-inline-script upload away from an XSS that the
    backend cannot defend against. This compounds Finding #1: the
    missing server-side image validation is exploitable in
    practice precisely because no CSP catches the resulting
    payload.

11. **`extractError` coverage gap is wider than previously noted.**
    I missed the `QuizEditorView.vue:333-336` inline copy in the
    last two analyses. The full set of call sites is now:
    - **3 module-level `extractError` functions** (auth.ts:178,
      `ChangePasswordView.vue:19`, `ResetPasswordView.vue:21`)
    - **5 inline `err.response?.data?.error ?? err.message ?? …`
      ternaries** (DashboardView.vue:20,34, HistoryView.vue:35,
      SessionDetailView.vue:45,125, ImageUpload.vue:56)
    - **1 inline ValidationProblemDetails handler**
      (QuizEditorView.vue:333-336 — the only one that handles
      `data.errors` correctly)
    - **3 SignalR-error or hard-coded "Failed to connect"**
      messages (useHostHub.ts:91, etc.) — these are correct as-is
      and should not be touched.
    
    Net deduplication: ~50 LOC deleted, +1 utility file (~30 LOC),
    +1 test file. Still the single highest pure-refactor
    reward/cost ratio in the repo.

### Proposed Task B — Plan: `UploadsController` server-side image validation + SPA Content-Security-Policy (Findings #1 + #10)
*Wider than the 2026-08-07/08/09 proposal.* Two halves:
 1. Backend: sniff the first 12 bytes for the actual magic number
    (JPEG/PNG/GIF/WebP have distinct signatures); reject anything
    where the bytes disagree with `Content-Type`; re-encode
    through `SixLabors.ImageSharp` to strip EXIF metadata and
    normalize dimensions; cap pixel area to (e.g.) 4096².
 2. Frontend: add a strict CSP `<meta>` to `frontend/index.html`
    (`default-src 'self'; img-src 'self' data:; style-src 'self'
    'unsafe-inline'; script-src 'self'; connect-src 'self'
    ws: wss:;`) and a `Referrer-Policy: strict-origin-when-cross-origin`
    meta. The `unsafe-inline` for `style-src` is required for
    Vue's scoped-style attrs and the Tailwind reset; document it
    in a comment so a future security pass doesn't blindly tighten
    it. Server-side `Response.Headers["X-Content-Type-Options"] = "nosniff"`
    in `Program.cs` via a small `SecurityHeadersMiddleware`.

~80 LOC total (40 backend, 25 frontend, 15 middleware). ~5 tests.
Smallest true security gap in the tree today, and the only
finding whose blast radius is "any user with an account can
upload arbitrary bytes that the SPA will render". The CSP
addition is what makes the upload validation *defense in
depth* rather than the single point of failure.
